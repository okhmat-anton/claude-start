# Формат единицы знания

Одна единица = одна ситуация, в которой её надо вспомнить, + одно действие. Не статья.

## Урок (`lessons/<name>.md`)

```markdown
---
name: stale-server-process            # = имя файла, kebab-case
description: Сервер на порту — не тот, что ты думаешь: lsof + время старта воркера против времени правок  # ≤160 символов, это строка INDEX
stack: [python, docker]               # any | python | fastapi | vue | nuxt | node | flutter | pymunk | ffmpeg | kie-ai | docker | selenium | llm | web-ui
status: mature                        # candidate — замечен в одном проекте; mature — в двух и более; archived — не показывается
created: 2026-08-24
seen_in: [3d-printer, planning]       # проекты, где урок всплывал; зрелость считается по этому списку
triggers:
  keywords: [не подхватил, старое поведение, --reload, порт занят]   # подстроки промта/команды, регистр не важен; ≥2
  commands: ['docker compose (up|restart)', 'uvicorn .*--reload']    # регулярки по команде Bash
  errors: ['address already in use']                                 # регулярки по тексту ошибок в промте
  paths: ['docker-compose*.yml']                                     # glob по путям файлов
---
# Заголовок одной фразой

Контекст: одна-две строки — где и при чём всплыло. Без имён проектов, путей, доменов, секретов.

Урок:
- действие в повелительном наклонении;
- признак, по которому ситуацию узнать заранее;
- цена ошибки одной строкой, если она нетривиальна.
```

Ограничения (проверяет `python3 tools/knowledge.py lint`): тело ≤30 строк прозы (код и таблицы не считаются),
описание ≤160 символов, ≥2 keywords, дата создания, seen_in не пуст. Тело длиннее — это две единицы, режь.

## Триггеры — главное поле

Урок, который не может сработать сам, не существует: хуки подмешивают единицы в контекст по совпадению
триггеров с промтом (`UserPromptSubmit`) и командой (`PreToolUse Bash`). Ключи пиши как основы слов
(«линтер», «зависл», «в корне репо»), а не как полные словоформы. Специфичные токены (`compare_digest`,
`--reload`, `2>&1`) весят вдвое больше обычных слов — добавляй их, если они есть.

## Жизненный цикл

1. `retro` в проекте находит урок → пишет в LESSONS.md проекта **и сразу** создаёт кандидата здесь
   (`knowledge.py new`), с `seen_in: [проект]`.
2. Другой проект наткнулся на то же → `knowledge-sync` добавляет его в `seen_in`; два проекта → `status: mature`.
3. Хуки показывают урок → `usage.json.shown` растёт. Агент применил → `knowledge.py hit <name>` → `applied`.
4. `knowledge-gc` раз в месяц: показан много раз и не применён ни разу → переформулировать или в архив;
   не показан за 90 дней → мёртвые триггеры; пересечение триггеров → слить.

## Улучшение (`improvements/<name>.md`)

Предложение, которое владелец уже принимал в одном проекте и которое стоит предложить в других: что сделать лучше
в решении задачи, в модуле, где шла работа, или в коде. Не упрощение (то не меняет поведения) и не баг. Рождается
в ревью на упрощение (simplify-review, /start 4.11) и в прогоне базы по проекту (skill `improve-sweep`); копится
с рейтингом — оценка владельца и оценка агента рядом, обе видны (правило владельца, 13.10.2026).

```markdown
---
name: new-feature-visible-before-data   # = имя файла, kebab-case
description: Новая возможность видна до первых данных …   # ≤160 символов, это строка INDEX — само предложение одной фразой
kind: solution                           # solution — решение задачи; module — модуль, где шла работа; code — код
stack: [web-ui]
status: candidate                        # candidate — принято в одном проекте; mature — в двух и более; archived — не предлагается
created: 2026-10-21
seen_in: [video-blade-2]                 # проекты, где улучшение принято; дописывает knowledge.py vote на accepted
benefit: 4                               # оценка выгоды агентом, 1–5, при создании
rating:                                  # оценка владельца 1–5 — среднее по проектам, пишет knowledge.py vote; пусто — не оценивал
triggers:                                # как у урока: по ним улучшение подбирается под задачу (промт, изменённые файлы)
  keywords: [вкладк, пункт меню, пустое состояни]
  paths: ['**/*.html', '**/*.vue']
---
# Заголовок одной фразой

Когда: признак, по которому улучшение применимо, — одна-две строки, без имён проекта и путей.

Предложение: вопрос владельцу его словами — что изменить, что он получит, цена («… Делаем?»).

Выгода: что получит владелец или пользователь. Цена: ~строк / файлов / минут.
```

Ограничения lint — как у урока (≤30 строк прозы, описание ≤160, ≥2 keywords, дата, seen_in), плюс `kind` из трёх,
`benefit` 1–5, `rating` пустой или 1–5, блоки «Когда» и «Предложение».

Жизненный цикл:

1. Ревью на упрощение или прогон по проекту предлагает улучшение владельцу. Каждый ответ — голос:
   `knowledge.py vote <name> --project <проект> --answer accepted|rejected|deferred|na [--score 1-5] [--reason "…"]
   [--memory <путь к simplify-memory.md проекта>]` (строка ответа в память проекта допишется сама) —
   история в `usage.json`; шапка — производная от неё и пересчитывается при каждом голосе: `seen_in` — принявшие
   проекты, `status: mature` — принято в двух и более, `rating` — средняя оценка; INDEX.md пересобирается там же.
   `na` («не применимо» — признака «Когда» в проекте нет) голосом против не считается и перепроверяется через полгода.
2. Оценку владелец ставит после того, как увидел результат (решение владельца, 21.10.2026): кнопки 5 / 4 / 3 / 1–2
   в финальном отчёте → `vote … --answer accepted --score N` → `rating` = среднее по проектам.
3. Своё улучшение, принятое в проекте и не найденное в базе, knowledge-sync обобщает и создаёт здесь кандидатом:
   `knowledge.py new <name> --improvement --kind solution|module|code --benefit N --seen-in <проект> --keywords "…"` —
   проект из `--seen-in` считается принявшим: его голос `accepted` записывается сразу, второй раз голосовать не надо
   (оценка владельца, если дана, — `vote … --answer accepted --score N`).
4. Подбор под проект — `knowledge.py improvements --project <проект> --stack … [--prompt … --files … --full]`:
   без решённого в этом проекте (отложенное — снова через 30 дней, «не применимо» — через полгода); порядок — совпадение с задачей, оценка владельца,
   баланс принято/отклонено, оценка агента.
5. `knowledge-gc`: отклонено в двух проектах и не принято нигде, оценка владельца ≤2, трижды отложено — в архив
   или переформулировать. Переформулировал — поставь в шапке `revised: <дата>`: ответы старше неё не считаются
   нигде (seen_in, зрелость, рейтинг пересчитаются при следующем голосе), и улучшение предлагается заново, в том
   числе отклонившим его проектам; пустой `seen_in` допустим только у переформулированного.

## Заметка по стеку (`stacks/<stack>.md`)

Шапка: `name`, `description` (≤160), `stack`, `triggers.keywords` (≥2), `triggers.paths`. Тело — справочник без
лимита длины: сюда идут факты об API, конвенции, грабли конкретной библиотеки. Хуки подмешивают заметку
целиком, поэтому держи её плотной.

## Скилл (`skills/<name>/SKILL.md`)

Стандартная шапка Claude Code (`name`, `description`) + `index:` — строка для INDEX ≤160 символов
+ `scope: global` для скиллов, которые ставятся в `~/.claude/skills/`, а не копируются в проект.

## INDEX.md

Генерируется из шапок: `python3 tools/knowledge.py index`. Руками не править.
