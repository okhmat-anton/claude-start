# Стек: Python + Selenium bot fleet + агент-воркер поверх REST

Конвенции для систем, где браузерные боты выполняют внешние действия (рассылки,
заполнение форм, сбор откликов), а задачи им раздаёт агентный воркер (Claude Code
и подобные) через API.

## Топология

- **API-first с первого дня.** Воркер получает протокол/задачу по REST и по REST же
  логирует результат. Ни воркер, ни UI не ходят в БД напрямую. Цена соблюдения —
  один слой, цена нарушения — переписывание, когда появляется второй/удалённый воркер.
- Каждая строка, принадлежащая пользователю, несёт `user_id` с самого начала, даже пока
  пользователь ровно один. Ретрофит владения — самая дорогая версия этой работы.
- Аутентификация: пароль/сессия для UI, персональный `X-API-Key` для воркеров. Ни одного
  неаутентифицированного write-эндпоинта.

## Инфраструктура прототипа

- SQLite + SQLAlchemy 2.0 + APScheduler в одном процессе на дешёвом VPS (~$10) —
  достаточно до первых реальных пользователей. Сигнал к переезду на Postgres — write-
  contention от нескольких параллельных браузерных воркеров, не раньше.
- Chrome в docker headful-под-Xvfb; на 1 ГБ RAM браузер конкурирует с приложением —
  это, а не CPU, определяет число параллельных воркеров.
- `create_all` создаёт таблицы, но НЕ добавляет колонки в существующие: идемпотентный
  `ALTER TABLE` на старте либо alembic.

## Боты — где ломается тихо

- **Статус `sent` только по позитивному подтверждению страницы**, никогда оптимистично
  после клика. Неподтверждённая отправка портит счётчик прогресса — единственное число,
  которому владелец доверяет.
- Ни одного `except: pass`. Каждая неудача — лог с целью, шагом и причиной + строка
  неудачной попытки в БД.
- Скриншот + снапшот DOM на каждом падении, путь — в строку попытки. По одному стектрейсу
  браузерный бот не чинится.
- Селекторы не выдумывать по памяти: проверять на живой странице и записывать проверенное
  в журнал уроков, иначе следующая сессия выводит их заново. У каждого селектора — либо
  фолбэк, либо явная ошибка, но не молчаливый no-op при изменившейся вёрстке.
- Явные ожидания по условию; `time.sleep` — не средство синхронизации.
- Рейт-лимиты и человекоподобный темп — конфигурация, не константы в коде. Ретраи
  ограничены с backoff; безлимитный ретрай против чужого сайта недопустим.
- Один браузерный профиль на аккаунт, профили и куки — вне git.
- Каждая задача идемпотентна или защищена claim'ом: краш посреди задачи не должен давать
  дубль отправки.
- Если площадка сигналит «стоп» (блок, запрет в правилах) — бот останавливается и
  показывает это владельцу, а не обходит.

## Данные

Персональные данные (резюме, контактные списки, собранные цели) живут в БД и на диске:
не в логах, не в коммитах, не отправляются никуда кроме адресата.
