# Взгляд Джобса

Тот, кто делал, видит задуманное. Человек видит то, что получилось. Поэтому смотрит отдельный
субагент, которому показывают только результат — без кода, плана и объяснений. Правило владельца
(27.09.2026): человеку по итогу должно быть интуитивно понятно и удобно — результат должен не
«работать», а сильно нравиться. «Выпускаем» — только если новичок сам, без подсказок, нашёл функцию
и довёл дело до конца. Для роликов и статей есть родственный скилл `viewer-reviewer`; этот — для
интерфейсов.

## Что в папке

- `prompt.md` — роль и правила субагента: Джобс со столом из инженера, дизайнера, продакта
  и новичка, девять вопросов, оценка из 10, вид ответа. В проекте кладётся в
  `.claude/agents/jobs-reviewer.md` (шапка: `tools: Bash, Read`, `model: opus`).
- `look.js` — глаза: настоящий Chrome без окна через протокол DevTools, без пакетов (Node 22+).
  Кадры компьютер 1440×900 и телефон 390×844, сценарии кликов по видимому тексту, выделение,
  клавиши; в отчёте — что можно нажать и что перекрыто, ошибки страницы, упавшие запросы, тексты
  диалогов. `open` — обычное окно Chrome для человека со входом. `--readonly` — любая запись
  блокируется. Ключ из `auth.json` уходит только на адрес приложения.

## 0. Есть ли что смотреть

Всё, что видит человек: страницы и их скрипты и стили, окна приложения, PDF, письма, сообщения
бота. Правка человеку не видна (маршрут без интерфейса, миграция, служебный скрипт) — одна строка
«Смотреть глазами нечего: …» и конец.

## 1. Стенд

Одноразовая копия приложения: отдельный процесс на свободном порту, пустые или пробные данные,
свой сгенерированный вход, никакого боевого env-файла, ключей ботов и платёжек (урок
`browser-test-stand`). Приложение пишет что-то рядом с кодом (резервные копии, загрузки) —
запускай с копии кода во временной папке, иначе стенд тронет защищённые папки проекта.
Для `look.js` стенд отдаёт `auth.json`:

```json
{"base": "http://127.0.0.1:5190", "login": {"path": "/api/auth/login", "json": {"username": "…", "password": "…"}}}
```

Пустой стенд — пустые экраны: заведи минимум пробных записей через API стенда, чтобы сделанное
было видно. Пустое состояние — тоже экран, покажи и его.

## 2. Бриф субагенту — мало и без подсказок

Даёшь: две-три фразы о продукте (кто пользуется, откуда, как часто, в чём ценность); задачу
пользователя его словами («хочу …» — зачем пришёл, а не что поменяли); старт — откуда человек
обычно начинает, чаще главная, а не новая страница: так проверяется, найдёт ли он функцию;
путь к `look.js`, `auth.json` и папку для кадров; что вне задачи.

Не даёшь: код, дифф, имена файлов, план, «что мы хотели сделать». Субагент, который знает замысел,
проверяет замысел, а не результат.

## 3. Запуск

Субагент `jobs-reviewer` с брифом. Его нет в списке (только что создан — список читается при
старте сессии) — `general-purpose` с моделью opus: «прочитай `.claude/agents/jobs-reviewer.md`
после шапки и работай строго по нему» + бриф. Прогон — до 8 запусков инструмента, 10–20 минут.

## 4. Замечания

- Поломка или недоделка в том, что сделано в задаче, — чинишь сразу, без вопроса.
- Вкус, новая функция, расширение задачи — вопросы владельцу одним пакетом кнопками,
  рекомендованный вариант первым; ответы разбираешь в базу стиля (скилл `style-base`).
- Вне задачи — одной строкой в отчёт, не трогаешь.

После правок — новый прогон свежим субагентом с тем же брифом. Максимум 3 круга.

## 5. Итог — владельцу в Chrome

`node look.js open <адрес на стенде> --auth <auth.json>` — обычное окно, уже со входом,
на странице с результатом. Стенд не гаси, пока владелец смотрит.

## 6. В отчёт

Первой строкой: «Взгляд Джобса: ВЫПУСКАЕМ, 8/10». Нет «выпускаем» после трёх кругов — так
и пиши первой строкой, что осталось, и слово «готово» не говори.

## Нельзя

- Показывать субагенту боевые данные и давать ему код, дифф и план.
- Смотреть на рабочем сервере с правами записи: второй взгляд на живой сайт — только `--readonly`.
- Верить автоматическому клику там, где он спорит с живой мышью: такое замечание субагент
  помечает «подтвердить руками», и ты подтверждаешь до правки.
