# Проверка по ТЗ

Агент говорит «готово», а кнопки нет, поле закрыто баннером, на картинке нет объекта из задания — владелец
находит это глазами, и время теряют оба. Правило владельца (12.11.2026): «готово» — только когда каждый пункт
сверен с результатом и сделан. В конце каждой задачи с правками, на любом уровне, строго. Уровень задачи
строгость не меняет; длину списка задаёт задание (ТЗ, промт, опись) — в простой задаче он обычно короткий.

## 0. Когда

- Перед словом «готово» в любой задаче с правками — из `done-check`, до финального отчёта. В «Ходе задач» —
  этап «проверка» (skill `task-log`).
- В начале задачи-копии («скопируй», «повтори как в …», «перенеси раздел из …») — раздел 5, до первой правки.
- Разделу нечего проверять (нет экрана, картинок, копирования) — одна строка в отчёте, почему пропущен.

## 1. Список требований — до сверки

Откуда: файл ТЗ (`technical-docs/<имя>/tz_<имя>.md`, старые — `tz_*.md`, спецификация, бриф) → текст задачи →
дописки владельца по ходу (в «Ходе задач» — отдельные пункты) → его ответы на вопросы → принятый план. Нет файла
ТЗ — собери из остального. ТЗ написано навыком `spec-write` — список уже готов: пункты П1…Пn с источниками и шаги
сценария «Что вы увидите, когда готово»; бери его как есть и добавь правки владельца с точек проверки.

Один пункт — одна вещь, которую можно показать: функция, экран, поле ввода, кнопка, состояние (пусто, ошибка,
загрузка), сообщение, правило (доступ, история, лимит); для картинки и видео — каждый объект, персонаж, надпись.
У пункта — источник: «ТЗ, стр. 37» или «владелец, 12.11: "…"». «Сделать удобно» — не пункт: переведи в
проверяемое или спроси.

Список пишется до сверки и под сделанное не подгоняется. Требование неясно — пункт «непонятно» (раздел 6).

## 2. Доказательство по каждому пункту

| Что | Доказательство |
|---|---|
| код, правило | файл:строка — открыл и прочитал сейчас, а не «помню, что писал» |
| поведение | маршрут и ответ (`curl`), тест, команда с выводом |
| видимое | кадр и строка из `report.txt` (раздел 3), объект на кадре (раздел 4) |

Нет доказательства — «нет». «Должно работать» — тоже «нет».

## 3. Поля и кнопки: есть, видны, нажимаются

1. Где смотреть: стенд с пробными данными (как в `jobs-review`), локальный адрес или статический сервер
   в папке страницы (`python3 -m http.server`). Рабочий сайт — только с `--readonly`.
2. Наличие — кадрами: сценарий на каждый экран из списка, компьютер и телефон. Клики и ввод — отдельными
   сценариями, по одной проверке: упавший шаг прерывает прогон этого размера экрана, и одна поломка спрячет
   остальные. Сообщения в строку «Можно нажать» не попадают — после клика шаг `wait` с их текстом.
   Кадры и одна проверка кликом:
   ```json
   {"start": "/form.html", "viewports": ["desktop", "mobile"], "steps": [{"shot": "top"}, {"scroll": 700}, {"shot": "low"}]}
   ```
   ```json
   {"start": "/form.html", "viewports": ["desktop", "mobile"], "steps": [
     {"type": "#name", "text": "Проба"}, {"click": "text=Сохранить"}, {"wait": "text=Сохранено"}, {"shot": "saved"}]}
   ```
   `node ~/.claude/skills/jobs-review/look.js run сценарий.json --out <папка> [--auth auth.json]`
3. В `report.txt` у каждого кадра строка «Можно нажать (N): [тег#id] «текст» …» — только то, что сейчас на
   экране; скрытое, нулевого размера и целиком за краем экрана туда не попадает. По каждому полю и кнопке из
   списка, на обоих размерах:
   - есть в строке без пометок — есть и видно;
   - «(перекрыто: …)» — нет: закрыто другим блоком, нажатие уйдёт в него;
   - «(неактивно)» — нет, если ТЗ не говорит, что в этом состоянии кнопка неактивна;
   - нет в строке — прокрути (`scroll`) и сними ещё кадр; нет и там — нет;
   - шаг клика с «ПЕРЕКРЫТ элементом …» или «НЕ УДАЛОСЬ» — нет.
   Поле без подсказки внутри выглядит как `[input#phone] «»` — сопоставляй по `id` и по подписи `label` рядом.
   Ошибки страницы и упавшие запросы в конце отчёта — к пунктам-функциям: функция с ошибкой — «нет».
4. Открой кадры (Read), телефон обязательно: кнопку, обрезанную краем, и нечитаемый текст отчёт не помечает.
5. Окна подтверждения инструмент всегда принимает — ветку «Отмена» в таком окне проверяй по коду. «Удалить»
   и другие необратимые кнопки нажимай только на стенде с пробными данными.
6. Лишнее, чего нет в ТЗ, но что мешает (баннер поверх кнопки), — находка в отчёт и вопрос владельцу.

## 4. Картинки и видео: все объекты на месте

1. Список объектов из задания (промт, ТЗ): каждый предмет, персонаж, надпись дословно; цвет, число и место —
   отдельными пунктами, если заданы.
2. Смотри картинку целиком и в увеличении (Read); у видео — ключевые кадры (`ffmpeg -i ролик.mp4 -vf fps=1/2
   кадры/%03d.png`, плюс начало и конец каждой сцены). Свежий взгляд надёжнее своего (паттерн `viewer-reviewer`):
   субагенту — только кадры и список объектов, без промта генерации; пусть сначала опишет кадр своими словами
   и только потом сверит со списком — иначе список подскажет ответ.
3. По каждому объекту: есть (в каком кадре) · нет · сомнительно. Надписи — по буквам. «Похоже по смыслу» —
   не «есть»: объект узнаётся без подсказки.
4. «Нет» — перегенерировать (недостающий объект в промте явно и первым) или исправить, потом проверить заново.
   «Сомнительно» — вопрос владельцу кнопками, с кадром.

## 5. Копирование: опись и вопросы до начала

1. До первой правки — опись того, что копируется, по коду и живой странице (`look.js` с `--readonly`; сервера
   нет — статический сервер в папке источника): каждая функция, экран, поле, кнопка, состояние, сообщение;
   откуда берёт данные и куда пишет; ключи, боты, внешние сервисы, тексты и бренд.
2. Проверь, работает ли сам источник. Его поломки — отдельным блоком описи: в копию не переносятся, источник
   без просьбы не правится, владельцу — одной строкой.
3. Каждый пункт: «понятно, как перенести» или вопрос. Неясно (копировать ли, чем заменить чужое — данные,
   ключи, сервис, бренд, — что значит «так же») — вопрос владельцу кнопками (AskUserQuestion), по одному,
   рекомендованный вариант первым. Не угадывать.
4. Опись с ответами — это список требований (раздел 1), его длину задаёт она; в конце — сверка по ней
   (разделы 2–4).

## 6. Итог

| # | Пункт | Источник | Итог | Доказательство |
|---|---|---|---|---|
| 4 | Кнопка «Удалить» | ТЗ, стр. 12 | нет | нет на экране: `report.txt`, desktop 01 и mobile 01 |

Итог пункта: сделано · нет · непонятно. Пункт, снятый владельцем, — «снят: кто, когда», в счёт не идёт.

- Всё «сделано» — в отчёте сразу после уровня строка «Проверка по ТЗ: 24 из 24» и где таблица (в отчёте или
  в карточке задачи).
- Есть «нет» — доделай и проверь заново эти пункты и то, что правка могла задеть.
- Есть «непонятно» — вопрос владельцу кнопками.
- Пока покрытие неполное, «готово», «всё сделано», «закончил» не звучат: строка «Проверка по ТЗ: 22 из 24 —
  нет: …; непонятно: …» и что осталось.

## Нельзя

- Подгонять список под сделанное, оставлять пункт без итога, засчитывать по памяти.
- Говорить «готово» при неполном покрытии, в том числе «готово, кроме …».
- Угадывать при копировании и на картинках: неясное — вопросом.
- Нажимать необратимые кнопки на рабочем сайте.
