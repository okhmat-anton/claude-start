# База стиля владельца

Вкус у владельца один на все проекты. Здесь копятся его правила — чтобы не спрашивать дважды
и чтобы ревью интерфейса мерило результат его меркой, а не усреднённой.

## Когда читать

- перед решением по интерфейсу или подходу — правило отсюда важнее твоего вкуса;
- перед вопросом владельцу: ответ уже есть — не спрашивай, примени правило и назови его вслух;
- в ревью интерфейса: нарушение правила — отдельное замечание со ссылкой на правило.

## Когда и как дописывать

После каждого ответа владельца на твой вопрос — кнопками или текстом:

1. Есть ли в ответе вкус или принцип, который поменяет решения в других задачах и проектах?
   Нет («да, выкладывай», выбор конкретного файла) — ничего не пиши и не упоминай.
2. Одно правило: коротко (до 15 слов), без имён проекта, файлов и страниц, утвердительно.
   Проверка: правило меняет хотя бы одно решение? «Делать удобно» не меняет ничего — не пиши.
3. Сверь с базой: такое уже есть — не дублируй, можно уточнить формулировку; противоречит
   старому — спроси владельца, какое верно, и замени старое, а не держи оба.
4. Строка в нужный раздел: `- Правило. — ДД.ММ.ГГГГ, <проект>`.
5. В отчёте задачи — строка «В базу стиля: …». На GitHub правило уходит в конце задачи вместе
   с остальным опытом — одним вопросом владельцу (skill knowledge-sync).

Правь этот файл в клоне базы знаний (`~/.claude/knowledge-repo/claude-start/knowledge/skills/style-base/SKILL.md`),
перед записью — `git pull`. Копию в проект не клади: она устареет в первый же день.

## Интерфейс

- Итог любой задачи — человеку интуитивно понятно и удобно пользоваться; «работает» — не критерий. — 27.09.2026, planning
- Админку делать в тёмной теме. — 27.09.2026, planning
- Главное меню — сверху, второстепенное (меню кабинета или раздела) — слева. — 27.09.2026, planning
- Важность задачи — пять кружков как звёзды, цвет по уровню: жёлто-зелёный → красный. — 27.09.2026, planning
- Всё, что меняется у записи, меняется прямо в списке — без захода в карточку. — 27.09.2026, planning

## Выбор решений

- Из вариантов выбирать максимально простой. — 27.09.2026, planning

## Как работает агент

- Поломки в своей работе агент чинит сам и перепроверяет; вкус и расширение задачи решает владелец — одним пакетом кнопками. — 27.09.2026, planning
- Новое правило работы агентов сразу уходит во все проекты: общая база и шаблон /start. — 27.09.2026, planning
- Обязательный шаг без предмета не делается ради галочки — пропуск называется одной строкой. — 27.09.2026, planning
- Перед записью урока — подтянуть репозиторий и проверить, не записал ли его уже другой агент. — 27.09.2026, planning
- Проверка глазами — по размеру правки: мелкая — свои кадры, новая страница или дизайн — полное ревью. — 27.09.2026, planning
