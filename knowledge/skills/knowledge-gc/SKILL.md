# Уборка базы знаний

База знаний живёт в клоне `~/.claude/knowledge-repo/claude-start` (путь — в `.claude/knowledge.json` проекта
или по умолчанию). Все команды ниже — из корня клона.

## 1. Отчёт
```
git pull --rebase --autostash
python3 tools/knowledge.py gc
```

## 2. Действия по секциям
- **Формат** — почини замечания lint сразу, без вопросов.
- **Кандидаты в двух и более проектах** — поставь `status: mature`. Это единственный путь к зрелости: повторы
  внутри одного проекта зрелостью не считаются.
- **Показывается, но не применяется** — прочитай единицу. Урок расплывчат → перепиши действием в повелительном
  наклонении. Триггеры слишком общие (одиночные частые слова) → сузь. Урок больше не актуален → `status: archived`.
  Каждое решение — кнопкой владельцу (AskUserQuestion, пакетом до 4 вопросов), архив без подтверждения не ставь.
- **Ни разу не показан** — триггеры мёртвые: добавь основы слов, шаблоны команд, тексты ошибок, glob путей.
  Проверь `python3 tools/knowledge.py match --prompt "<типичный запрос>"` — единица должна попасть в топ-3.
- **Похожие единицы** — слей в одну (перенеси уникальные пункты «Урока», объедини seen_in и триггеры, второй файл
  удали) либо разведи триггеры, если темы разные.
- **Слишком длинные** — разрежь: одна единица = одна ситуация срабатывания.
- **Синхронизация** — клон отстаёт → уже сделал pull в п. 1; впереди или грязный → закоммить и запушь (п. 4).

## 3. Проверка
```
python3 tools/knowledge.py lint && python3 tools/knowledge.py index && python3 tools/evals.py
```
Если урок переименован — обнови кейс в `evals/cases.json`. Добавь кейс на каждую единицу, у которой чинил триггеры.

## 4. Коммит
Покажи владельцу сводку (слито N, архивировано M, продвинуто K, переформулировано L), дождись подтверждения,
затем `git commit -m "knowledge: gc <дата> — <сводка>"` и `git push`. Запиши дату уборки в `knowledge/usage.json`
ключом `_gc.last` (через `python3 -c`), чтобы SessionStart знал, когда напоминать в следующий раз.
