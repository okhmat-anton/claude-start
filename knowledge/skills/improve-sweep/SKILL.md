# Прогон базы улучшений по проекту

База улучшений (`knowledge/improvements/` в клоне базы знаний, формат — `knowledge/FORMAT.md`) — предложения,
которые владелец уже принимал в одном проекте: что сделать лучше в решении задачи, в модуле или в коде. Этот скилл
пробует их на текущем проекте. Запускается по слову владельца, не по расписанию и не вместе с daily-sync (правило
владельца, 13.10.2026: проверка по внешним данным — по кнопке). Клон и его путь — `localPath` в `.claude/knowledge.json`
проекта (по умолчанию `~/.claude/knowledge-repo/claude-start`); все команды ниже — из корня клона.

## 1. Подбор
```
git pull --rebase --autostash
python3 tools/knowledge.py improvements --project <имя проекта> --stack <стек из .claude/knowledge.json через запятую> --full
```
Список уже без решённого в этом проекте (отложенное вернётся через 30 дней, «не применимо» — через полгода); сверху — с лучшей оценкой владельца и
балансом принято/отклонено. Нужен срез по теме — добавь `--prompt "<тема>"` и `--files <пути через запятую>`.
Пусто — одна строка «в базе нет улучшений под этот проект» и конец.

## 2. Применимость — по коду, не по описанию
Для каждого улучшения открой место в проекте, куда оно легло бы (экран, модуль, маршрут), и проверь блок «Когда»:
признак есть — кандидат; признака нет (уже так сделано, такой сущности в проекте нет) —
`python3 tools/knowledge.py vote <name> --project <проект> --answer na`, владельцу не показывай.
Кандидаты не режутся: все идут владельцу, по рейтингу (решение владельца, 21.10.2026: улучшения — без лимита, по выгоде).

## 3. Вопросы владельцу — пакетами кнопок
AskUserQuestion, по 4 вопроса за вызов, пока кандидаты не кончатся или владелец не скажет «хватит». Вопрос называет
экран и предмет своими словами, без внутренних терминов, и несёт рейтинг: «Список задач: действия у записи спрятаны
в меню «ещё». Вынести видимыми кнопками? Принято в 1 проекте, оценка владельца 5, агента 3; цена ~30 строк».
Варианты: «Делаем», «Нет», «Позже». Заголовок — «Улучшение N», имя единицы — в скобках в конце вопроса: по нему
записывается ответ. Перед вопросом — база стиля (skill style-base): правило уже отвечает — применяй без вопроса
и назови правило.

## 4. Запись каждого ответа — сразу
```
python3 tools/knowledge.py vote <name> --project <проект> --answer accepted|rejected|deferred --reason "…" \\
  --memory <проект>/.claude/simplify-memory.md
```
`--memory` сам допишет строку `| дата | улучшение из базы <name>: суть | ответ | причина |` в память проекта.
Причину отказа называй всегда: она уходит в историю и пригодится, когда улучшение будут переформулировать.
Не записал — следующий прогон спросит то же самое, а рейтинг останется слепым.

## 5. Принятые — задачей по уровню
Один вопрос на весь пакет принятых (заголовок «Сложность», skill task-tier): простая / средняя / сложная; дальше —
обычный цикл по уровню (план, правки, самопроверка, ревью и упрощение по уровню, коммит и push). Несколько принятых —
по одному, каждое своим коммитом, чтобы откат был точечным. «Позже» — в блок «что осталось» отчёта, не в код.

## 6. Оценка — после того, как владелец увидел результат
В финальном отчёте — один вопрос на каждое сделанное улучшение (по 4 за вызов): «Оценка улучшения <суть>» —
5 / 4 / 3 / 1–2 → `python3 tools/knowledge.py vote <name> --project <проект> --answer accepted --score <N>`.
Владелец не ответил — оценка остаётся пустой, «принято» уже записано. Оценка владельца и оценка агента хранятся
рядом, обе видны (правило владельца, 13.10.2026; оценка — после результата, 21.10.2026).

## 7. В базу
`git commit -m "knowledge: improvements — голоса <проект> (<дата>)" -- knowledge/usage.json knowledge/improvements knowledge/INDEX.md`
и `git push` в клоне (push отклонён — `git pull --rebase` и повтор). В отчёте задачи — блок: предложено N, принято /
отклонено / позже / не применимо, сделано, оценки.

## Нельзя
- Делать улучшение без слова владельца: автономный прогон — только `deferred` и список в отчёте.
- Предлагать решённое в этом проекте или отклонённое с причиной, которая всё ещё верна.
- Подменять «не применимо» на «отклонено»: `na` — не голос против, улучшение не теряет рейтинг.
- Запускать по расписанию или из daily-sync без слова владельца; сокращать список кандидатов «чтобы не утомлять».
