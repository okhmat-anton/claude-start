# PDF-отчёт — оформленный, а не распечатка текста

Задача: превратить готовый markdown-текст (бизнес-план, КП, отчёт по
исследованию) в PDF, который приятно листать — не «Word, распечатанный
в PDF», а документ с обложкой, инфографикой и вёрсткой. Ниже — рабочая
архитектура; готовая реализация (набор CSS/JS + скрипт-оркестратор) — в
проекте-источнике (см. пометку внизу), переносить в новый проект как
самостоятельный небольшой инструмент, не как библиотеку.

## Архитектура (три части)

1. **HTML-скелет из markdown.** Простой построчный конвертер (заголовки →
   секции с номером, таблицы, списки, `**bold**`/код) кладёт текст документа
   в разметку с классами компонентов (плитки цифр, карточки, врезки,
   баннер-картинка, график). **Важная ловушка**: если конвертер вызывает
   inline-разбор (`**bold**`, ссылки) отдельно на каждую физическую строку
   списка вместо всего пункта целиком — жирный текст, перенесённый на свою
   строку внутри пункта списка, останется буквальными звёздочками в выводе.
   Либо разбирать список целиком одним вызовом, либо не переносить строку
   посреди выделения.
2. **Набор компонентов + графики через JSON-спеку.** Обложка на всю страницу,
   плитки главных цифр, врезки (вывод/риск/предупреждение), карточки тарифов,
   баннер-картинка с подписью. График — `<figure data-chart='{JSON}'>`,
   единый рендерер разбирает JSON и рисует SVG по ширине колонки: типы
   столбцы / горизонтальные полосы / линии по времени / кольцо долей /
   составные полосы / этапы по датам (гант, с вехами) / карта
   «вероятность × влияние». Одна проверенная цветовая палитра на все типы —
   не изобретать под каждый график заново.
3. **Печать HTML → PDF headless-браузером.** Chrome `--headless=new
   --print-to-pdf`. Готовность файла проверять **по содержимому** (последние
   байты PDF — `%%EOF`), а не по факту выхода процесса или наличию файла:
   старый PDF на том же пути пройдёт проверку «файл существует» раньше, чем
   браузер допечатает новый, и по ошибке уйдёт версия «до» правок; сам Chrome
   без сети иногда не завершает процесс — ждать конкретно готовый файл, затем
   убивать группу процессов принудительно. Любой элемент вёрстки, вылезший за
   ширину колонки печати (декоративная стрелка шага, запрет переноса в
   таблице), браузер молча ужимает — **весь документ целиком**, и обложка без
   полей внезапно получает белую кромку; ловится только просмотром растра
   (см. ниже), не чтением HTML-исходника.

## Картинки — нейросеть, без цифр и текста

Промт картинки — только настроение и стиль (свет, цвет, композиция, предмет),
явно добавить в промт запрет цифр/букв/логотипов/водяных знаков: цифры и
факты живут в тексте и графиках, не на картинке. Обложка — портретная
(вертикальная), баннеры к разделам — альбомные. Одна серия картинок в едином
визуальном стиле на весь документ (общая палитра/свет/цветокоррекция в промте).

## Обязательный шаг — просмотр растром до отправки

Печать каждой страницы готового PDF в PNG (`pdftoppm` или аналог) и чтение
их как изображений перед показом заказчику. Обрезанные подписи, наложения
элементов, белая кромка у обложки без полей и полупустые страницы видны
только на растре — их не поймать чтением HTML или JSON-спеки графика.

## Чек-лист перед отправкой

- Текст и цифры документа не изменились по смыслу — вёрстка меняет вид, не
  содержание (не округлять по-своему, не выбрасывать строки, не дописывать
  выводов от себя).
- На каждую таблицу с сопоставимыми числами — свой график рядом (не вместо
  таблицы, а рядом: график — для глаза, таблица — для точной цифры).
- Каждая страница просмотрена растром.
- Источник документа обновлялся уже после того, как собрали PDF? —
  пересобрать из последней версии, не патчить старый PDF вручную.
