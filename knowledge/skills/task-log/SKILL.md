# Ход задач

Правило владельца (23.10.2026): протокол работы агентов улучшают по фактам, а не по ощущениям — где уходит
время, сколько ждут ответа владельца, что срывается. Поэтому каждая задача с правками в каждом проекте пишется
в «Ход задач» планировщика: `https://plan.akm-technologies.org/task-runs.html`, API `/api/task-runs`. Владелец
видит каждую задачу полоской по цветам этапов, итог за период и «оборвалась» у брошенных.

## 1. Когда

- Любая новая задача с правками — сразу после уровня (skill `task-tier`), до разбора, плана и первой правки.
- Одна задача владельца — одна запись; новая задача в той же сессии — новая запись. Вопрос без правок,
  ответ на свой вопрос, уточнение по текущей задаче — запись не заводится, этап идёт дальше.

## 2. Ключ

Порядок поиска, первый найденный и берётся:

1. переменная окружения `PLANNING_API_TOKEN`;
2. файл `.env` в корне проекта, строка `PLANNING_API_TOKEN=…` — читай маленьким скриптом, не печатай значение;
   хук проекта запрещает путь к файлу окружения в команде — тогда вызов API делает тот же скрипт, а ключ
   в команду не попадает;
3. ключ проекта `pk-…` из карточки проекта в планировщике (гайд проектного агента) — он пишет только под своим проектом;
4. ничего нет — **спроси у владельца кнопками** (AskUserQuestion, заголовок «Ключ API»): «Для журнала хода задач
   нужен ключ API планировщика (Настройки → Доступ по API). Вставь ключ или выбери «Без журнала»». Ключ получил —
   сохрани в `.env` проекта строкой `PLANNING_API_TOKEN=…` и проверь, что `.env` в `.gitignore` (нет — добавь).

Отказал или не ответил — работай дальше без записи и скажи об этом в отчёте одной строкой («ход задачи не
записан: нет ключа»). Ключ в чат, в логи, в код и в коммиты не попадает никогда.

## 3. Три вызова

```bash
# 1. Начал задачу — сразу после уровня. В ответе id — запомни (первая строка плана).
curl -s -X POST https://plan.akm-technologies.org/api/task-runs \
  -H "Authorization: Bearer $PLANNING_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"project":"<название проекта из реестра GET /api/projects/registry или папка репозитория>",
       "title":"<задача одной строкой, словами владельца>","tier":"простая | средняя | сложная",
       "agent":"claude-code · <модель>","stage":"разбор"}'

# 2. Перешёл к следующему шагу — прошлый этап закрывается сам, в момент запроса.
curl -s -X POST https://plan.akm-technologies.org/api/task-runs/<id>/stages \
  -H "Authorization: Bearer $PLANNING_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"stage":"правки","note":"что именно делаешь (по желанию)"}'

# 3. Закончил или сорвалось.
curl -s -X POST https://plan.akm-technologies.org/api/task-runs/<id>/finish \
  -H "Authorization: Bearer $PLANNING_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"status":"done | failed | cancelled","note":"итог одной-двумя строками: что сделано, что осталось"}'
```

Потерял id (сжатие контекста, новая сессия) — найди открытую запись:
`GET /api/task-runs?status=running&project=…`. Полный протокол с ответом сервера — поле `protocol`
в ответе `GET /api/task-runs`.

## 4. Этапы — общий словарь, по шагам цикла

| Этап | Когда отмечать |
|---|---|
| разбор | уровень, prompt-gate, вопросы владельцу, разведка кода |
| план | план-чеклист составлен и показан |
| ожидание | ход закончился вопросом владельцу (план, кнопки, «залить?») — пока он не ответил |
| правки | сам код |
| проверка | тесты, линтер, прогон руками, свои кадры экрана |
| ревью | взгляд Джобса или code-review и починка по замечаниям |
| упрощение | ревью на упрощение и улучшения, правки по нему |
| отчёт | финальный отчёт, чек-лист готовности, вопросы в конце |
| коммит | коммит и push |
| выкладка | выкладка на сервер и проверка после неё |
| retro | уроки, база знаний, база стиля |

Цвета закреплены за названиями, поэтому этап — из словаря; свой — редко и только если ни один не подходит.
Тот же этап второй раз подряд — не ошибка, обновится только заметка. Запись без новостей шесть часов страница
показывает как оборвавшуюся: задача правда идёт — отметь текущий этап ещё раз.

## 5. Закрытие

- `done` — задача закончена целиком: после push, а если была выкладка — после неё и проверки.
- `failed` — остановился на ошибках, которые не сошлись, или задачу нельзя закончить.
- `cancelled` — владелец отменил или отложил.
- Итог — простым языком: что сделано, что осталось, что пропущено по уровню. Его читает владелец.

## Нельзя

- Заводить запись в конце задним числом: смысл полоски — честное время, этапы отмечаются в момент перехода.
- Размазывать ожидание ответа владельца по рабочим этапам — для него есть «ожидание».
- Останавливать работу из-за журнала: нет ключа, сервер не ответил — одна строка в отчёте и дальше.
- Светить ключ: в команде только переменная или скрипт, в чате и логах ничего.
- Писать внутренние обозначения в названии и итоге — их читает владелец, язык простой русский.
