# API discovery — когда живой API опережает документацию

Контекст: данные идут через REST API (свой или сторонний), описание регулярно отстаёт от кода. Адрес страницы
документации, угаданный по аналогии с соседними, сайт тихо подменяет общей страницей — пересказ выглядит как
ответ про не тот эндпоинт.

Урок:
- Порядок поиска недостающего эндпоинта или поля: вторичные доки → журнал уроков проекта (могли уже найти) →
  форма живого GET-ответа (новые поля появляются в API раньше доков; `*_id` и счётчики в `/summary` подсказывают
  эндпоинты) → пробный PUT/POST на ОДНОМ объекте с проверкой echo → только потом батч.
- У стороннего сервиса с сайтом доков первым делом тяни машинную спецификацию из корня (`/openapi.json` у
  Mintlify-подобных): там есть маршруты, которых нет в оглавлении. Страницы читай только за деталями формата ответа.
- Ничего не выдумывай по памяти и не пиши «осторожных хеджей» про эндпоинты, чей статус уже установлен, — сверяйся с журналом.
