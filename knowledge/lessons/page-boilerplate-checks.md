# Обязательные подключения страниц проверяет программа, а не внимательность

Контекст: проект без сборки, каждая страница — отдельный HTML, общие модули подключаются строкой руками. Три
жалобы за месяц («разные шапки», «высота поля слетает», «на сервере страница не открывается») — каждый раз одна
забытая строка. Не ловится ни линтером, ни ревью: смотрят на добавленное, а не на отсутствующее. Автор правила
нарушил его в той же сессии, где сформулировал.

Урок:
- Список обязательных подключений — исполняемая проверка внутри общей команды проверки, не пункт в документе.

| Проверка | Чем оборачивается пропуск |
|---|---|
| файл в списке копирования образа | локально работает, на сервере 404 |
| есть меню → общий стиль шапки, и ПОСЛЕ встроенного `<style>` | шапка отличается от соседних |
| есть поле ввода → модуль размеров и свой `id` у поля | размер слетает, модуль не знает, чей он |
| есть меню → общий модуль панели агента | со страницы нельзя позвать агента |

- Исключения проверка знает сама (страницы-перенаправления в две строки), иначе начнёт врать и её отключат.
- Негативный прогон обязателен: заведомо битая страница должна валить проверку с КАЖДОЙ причиной отдельно.
- Первый прогон найдёт то, чего не искали: две страницы без панели и поле без id, пропущенные ручным обходом десятью минутами ранее.
