# Обязательные подключения страниц проверяет программа, а не внимательность

Стек: проект без сборки, где каждая страница — отдельный HTML со встроенным скриптом,
а общие модули (стили шапки, запоминание размеров полей, панель агента) подключаются
руками строкой в каждом файле. Проверено на ванильном фронтенде поверх Node без
зависимостей; применимо к любому проекту с ручным списком подключений и явным
перечнем файлов в образе.

## Как это выглядит со стороны заказчика

Разбор его собственных сообщений за месяц дал три жалобы, к которым он возвращался
по нескольку раз:

- «у меня разные шапки меню на разных страницах»;
- «ширина не меняется», «высота поля слетает после перезагрузки»;
- «на сервере нет превью / страница не открывается» — при том, что локально всё работало.

Ни одна не была сложной ошибкой. Каждый раз это была **одна забытая строка
подключения**. Дефект такого рода не ловится ни синтаксической проверкой, ни линтером,
ни ревью кода — правка выглядит правильной, потому что смотрят на добавленное, а не
на отсутствующее.

## Правило

Список обязательных подключений — **исполняемая проверка внутри общей команды
проверки**, а не пункт в документе конвенций. Документ забывается, в том числе
автором. В той же сессии, где это правило формулировалось, новая страница была
выложена без общего стиля шапки — то есть автор правила нарушил его немедленно.

Минимальный набор проверок на каждую страницу:

| Проверка | Чем оборачивается пропуск |
|---|---|
| файл перечислен в списке копирования образа | локально работает, на сервере 404 |
| есть меню → подключён общий стиль шапки | шапка отличается от соседних страниц |
| есть поле ввода → подключён модуль размеров | размер, потянутый мышкой, слетает |
| у каждого поля ввода свой `id` | модуль не знает, чей размер запоминает |
| есть меню → подключён общий модуль панели агента | со страницы нельзя позвать агента |

## Три вещи, без которых проверка бесполезна

**Порядок подключения — часть правила.** Общий стиль шапки грузится **после**
встроенного `<style>` страницы. Иначе местные правила перебивают общие, файл
формально подключён, проверка зелёная, а шапка всё равно другая.

**Исключения проверка знает сама.** Страницы-перенаправления в две строки не имеют
ни меню, ни полей ввода. Если их не отсеять по признаку (короткий файл с переходом
на другой адрес), проверка начнёт врать, и её отключат.

**Негативный прогон обязателен.** Заведи заведомо битую страницу — без подключений,
с полем без `id`, не внесённую в список копирования — и убедись, что проверка падает
и называет **каждую** причину отдельно. Проверка, которую видели только зелёной,
ничего не гарантирует.

## Побочный эффект, ради которого стоит начинать

Первый же прогон находит то, чего не искали: в описанном случае — ещё две страницы
без панели агента и поле ввода без `id`, пропущенное при ручном обходе тем же
человеком десятью минутами ранее. Ручной обход глазами пропускает даже там, где
точно знаешь, что ищешь.
