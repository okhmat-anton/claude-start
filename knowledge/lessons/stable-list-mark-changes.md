# Рабочий список по дате создания, а не по updated_at: изменения — метками и подсветкой до открытия, не перестановкой строк

Контекст: рабочий список (песни, задачи) сортировался по `updated_at` — любая правка поднимала запись наверх, и
человек терял, где какая; просьба была «не подкидывать, а помечать».

Урок:
- Сортируй рабочий список по дате создания (новые сверху), правка порядок не меняет.
- Изменения показывай метками и подсветкой до открытия записи: `seen_at` пиши при открытии напрямую в базу, без
  журнала действий и без `updated_at`; подсвечивай только чужие изменения (агент, новые результаты), свои человек видит.
- Признак: `sort=[("updated_at", -1)]` у списка, по которому человек ориентируется глазами.
