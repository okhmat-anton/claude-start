# Публичный API с кэшем на минуту прячет свежие правки — то, что человек правит и сразу показывает, отдавать с no-cache

Контекст: публичный API сайта отдавал всё с `Cache-Control: public, max-age=60` — удобно для цен и библиотеки.
Человек переставил треки альбома в кабинете, открыл публичную ссылку — порядок старый: браузер взял ответ из кэша.
Ревью записало это как поломку синхронизации, хотя база была верной.

Урок:
- Объект, который человек правит и сразу показывает другим (альбом, профиль, страница записи), публичный API
  отдаёт с `Cache-Control: no-cache`; кэш на минуту — только для редко меняющихся справочников (цены, FAQ, библиотека).
- Один общий набор заголовков на весь публичный роутер — ловушка: новый эндпоинт наследует кэш молча. Заголовки
  кэша задавай явно у каждого эндпоинта или по типу данных.
- Жалоба «на сайте старое» → первым делом заголовки ответа (`curl -D -`), потом логика.
