# Страница с действиями через ?err= принимает err/saved в обработчике и кладёт в контекст; тест отказа проверяет, что страница отдаёт err, не только редирект

Контекст: новые страницы не принимали `err` из адреса и не клали его в данные — отказ сервера (нет хранилища, нет
поставщика) до человека не доходил. Ревью выставило два «блокера» за молчание, хотя сервер отвечал правильно и
тесты на редирект `?err=` были зелёными.

Урок:
- Паттерн «действие → редирект на страницу с `?err=код` / `?saved=id`» живёт в двух местах: обработчик страницы читает
  параметры и кладёт их в контекст, компонент показывает их у действия-отправителя.
- Тест отказа утверждает оба конца: редирект с `?err=` и что GET страницы с этим параметром отдаёт `err` в данных.
- Признак: новая страница со старым набором действий — сверь по соседней странице, какие служебные параметры она принимает.
