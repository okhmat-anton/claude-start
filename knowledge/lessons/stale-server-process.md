# Сервер на порту — не тот, что ты думаешь

Контекст: статика читается с диска при каждом запросе, а роуты, конфиг и пулы процессов живут в памяти давно
запущенного сервера. Симптом «страница новая, поведение старое». Из практики: docker и локальный dev-инстанс
на одном порту в разные дни; uvicorn + ProcessPoolExecutor(spawn).

Урок:
- Перед «пересобрать» или «перезапустить» выясни фактический процесс на порту: `lsof -nP -iTCP:<порт> -sTCP:LISTEN`,
  затем `ps -o lstart,command -p <pid>`. Это может быть не докер, а локальный процесс, стартовавший до правок.
- `--reload` не гарантирует подхват: сверяй время старта воркера с временем правок, а не верь флагу.
- Пул воркеров держит код, загруженный при создании пула; отсутствие дочерних процессов = пул ещё не создан =
  следующий вызов возьмёт новый код без рестарта.
- Симптом «новая статика + старое поведение» диагностируй с версии процесса, а не с кода фронта.
