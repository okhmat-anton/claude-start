# Сервер на порту — не тот, что ты думаешь

Статика читается с диска при каждом запросе, а роуты, конфиг и пулы процессов
живут в памяти давно запущенного сервера. Они расходятся молча: страница новая,
поведение старое.

- Прежде чем «пересобрать контейнер» или «перезапустить сервис», выясни
  фактический процесс на порту: `lsof -nP -iTCP:<порт> -sTCP:LISTEN`, затем
  `ps -o lstart,command` по PID. Это может оказаться не докер, а локальный
  dev-процесс (и наоборот), запущенный задолго до твоих правок.
- `--reload` дев-сервера не гарантирует подхват: проверяй время старта воркера
  против времени правок, а не верь флагу.
- Пул воркеров (multiprocessing/spawn) держит код, загруженный при создании
  пула. Свежий воркер импортирует модули с диска заново — уже созданный живёт
  со старыми. Отсутствие дочерних процессов = пул ещё не создан = следующий
  вызов возьмёт новый код без рестарта.
- Симптом «новая статика + старое поведение» диагностируй с версии процесса,
  а не с кода фронта.

(из практики: python/uvicorn + ProcessPoolExecutor(spawn), докер и локальный
dev-инстанс на одном порту в разные дни)
