# Прод-данные правим ops-инструментами репозитория, а не руками

Контекст: инцидент в данных на проде (расписание разъехалось, в запись попало лишнее). Соблазн — ssh и SQL
«на месте»: не воспроизводимо, не тестируется, не откатывается и не оставляет следа для следующего такого же случая.
Диагностика, печатающая только шапки записей, бесполезна: гипотезы строятся по коду и множатся.

Урок:
- Любая правка прод-данных — ops-задача в репозитории, через make-таргет: диагностика read-only (первой, безопасна
  для повтора); ремонт идемпотентный (повторный прогон ничего не меняет) с `--dry-run` по умолчанию; точечные
  операции с явными аргументами и печатью «было → стало»; инструмент отказывается трогать запись с реальными
  пользовательскими данными («факт важнее плана»); юнит-тест на чистой функции: применение + повтор = без изменений.
- Диагностика показывает СОДЕРЖИМОЕ: значения, то, как их видит парсер, релевантные настройки пользователя.
  Флаг «показать содержимое» деплой вместе с фиксом — один флаг дешевле трёх взаимоисключающих гипотез.
