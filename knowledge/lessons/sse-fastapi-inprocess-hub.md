# Живые обновления без очередей: хаб в памяти процесса и подписчик с отметками

Контекст: кабинет должен показывать правки агента через API без перезагрузки, а стек ограничен приложением,
базой и прокси (без Redis, брокеров и Socket.IO); сервер — один воркер на машине с 2 ГБ памяти.

Урок:
- Поток — `StreamingResponse(text/event-stream)` с заголовками `Cache-Control: no-cache, no-transform` и
  `X-Accel-Buffering: no` (иначе nginx копит ответ); `: ping` каждые ~25 с, короче `proxy_read_timeout`.
- Подписчик хранит не очередь кадров, а множество «что изменилось» (область × раздел) и `asyncio.Event`:
  десять записей подряд дают один кадр, память не растёт на медленной вкладке.
- Публикуют точки записи (строка журнала действий = событие); запись мимо общего сервиса обязана звать publish —
  закрепи тестом-обходом модулей.
- Срок потока ограничен (~15 мин) с полем `retry`, браузер переподключается сам; лимиты на пользователя и на
  процесс, лишнему подписчику — 503 с Retry-After, а не вытеснение старого (вытеснение даёт лавину перечитываний).
- Хаб в памяти = ровно один воркер; закрой потоки в lifespan на выходе и запускай сервер с
  `--timeout-graceful-shutdown N`, иначе рестарт ждёт открытые соединения.
- Клиент перечитывает страницу при каждом `open` потока: событие между загрузкой страницы и подключением иначе теряется.
