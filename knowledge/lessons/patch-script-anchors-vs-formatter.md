# Якоря патч-скрипта ломаются о форматер: проверять все до записи

Контекст: правки файлов шли скриптами «найти точный фрагмент → заменить» с проверкой `count == 1`. Пять раз за одну
сессию якорь не находился, потому что форматер (ruff format) успел переложить строку после предыдущей правки, а текст
для якоря брался из памяти, а не из файла. Один скрипт записал половину правок и упал на середине — файл остался в
промежуточном состоянии, и следующая правка легла на него.

Урок:
- В одном скрипте: сначала все `assert` на якоря, потом все замены, и только в конце одна запись файла — либо всё,
  либо ничего.
- Якорь берётся из файла, прочитанного прямо перед правкой, а не из своей памяти; после записи сразу форматер, и
  следующая правка читает файл заново.
- Для строк, которые форматер точно переложит (длинные вызовы, словари), — регулярное выражение по уникальному
  фрагменту или правка по AST, а не точная многострочная цитата.
- Признак заранее: правка идёт в файл, который уже правили в этой сессии и прогоняли через форматер.
