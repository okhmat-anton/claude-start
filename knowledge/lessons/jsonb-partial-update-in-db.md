# Ключ JSON-поля, который пишут двое, меняют в самой базе

Контекст: пока фоновая задача собирала результат и писала в JSON-поле строки свой ход, человек отмечал в том же поле
действие. Запись целого словаря из ORM-объекта, прочитанного раньше, затирала чужой ключ.

Урок:
- Один ключ общего JSON-поля меняй запросом `UPDATE … SET поле = jsonb_set(поле, '{ключ}', значение) WHERE …` с
  условием на состояние строки, а не чтением и записью всего словаря; финальную запись делай под замком строки
  (`with_for_update`) и после `refresh`.
- В SQLAlchemy значение для `jsonb_set` — сам словарь: `cast({"step": s}, JSONB)`. `cast(json.dumps(...), JSONB)`
  сериализует строку второй раз, и в поле оказывается JSON-строка — экран получает текст вместо объекта.
- Служебные ключи (ход работы, черновик) убирай из поля, когда работа закончена, и не отдавай их в «данные человека».
- Тест: записать ключ фоновым путём, изменить соседний ключ запросом, прочитать оба.
