# Запись на GET + публикация события = петля

Контекст: открытие страницы записи ставило «просмотрено» и публиковало событие; подписанная вкладка перечитывала
страницу, та снова ставила «просмотрено» — бесконечный поток запросов, заметный только по журналу сервера.

Урок:
- Запись, которая происходит при чтении (seen_at, прогрев превью, посев по умолчанию), событие не публикует —
  это не изменение данных пользователя.
- Своё эхо отсекай по идентификатору вкладки из заголовка запроса (ContextVar в middleware); фоновая задача,
  начатая запросом, отвязывается от него явно, иначе её события тоже считаются «своими» и теряются.
- Проверка: открой страницу и смотри журнал запросов десять секунд — тишина. Любая «запись на GET» — кандидат на петлю.
- Родственное: live-update-own-echo-autosave (постоянная метка источника вместо номера вкладки).
