# Набор правил — явно; конфликт с идиомой фреймворка — конфигом

Контекст: дефолтный набор правил линтера меняется между версиями (у ruff 0.16+ заметно шире): без конфига
линтер ругается на идиомы фреймворка. Даже при явном `select` новое правило из включённой группы ловит штатный
паттерн: bugbear B008 «вызов в значении аргумента по умолчанию» против `Depends`/`Cookie`/`Header`/`Query` в FastAPI.

Урок:
- В конфиге явно перечисли стартовый набор (синтаксис, неиспользуемое/неопределённое, порядок импортов) и
  расширяй его осознанно после чистки; явный `select` защищает от смены дефолтов при обновлении линтера.
- Конфликт правила со штатной идиомой чини точечной настройкой самого правила с комментарием почему (у ruff:
  `lint.flake8-bugbear.extend-immutable-calls` со списком этих вызовов) — не `noqa` по коду и не отключением
  правила целиком: конфиг чинит все текущие и будущие места, правило продолжает ловить настоящие ошибки.
