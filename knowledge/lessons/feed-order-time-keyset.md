# Лента по времени, листание по той же паре (время, id)

Контекст: записи, посеянные задним числом (демо-люди, импорт), получили id больше, чем свежие записи людей; лента по id
ставила посты месячной давности над вчерашними. Листание шло по `id < before_id` — с порядком по времени оно бы
теряло и повторяло записи.

Урок:
- порядок ленты — по времени создания и вторым ключом по id в том же направлении: равное время не перемешивает строки;
- листание — по той же паре: курсор — id последней показанной записи, сервер берёт её время и отдаёт
  `(created_at, id) < (время курсора, id курсора)`;
- курсор успели удалить — листай по id, а не с первой страницы, иначе в списке повторы;
- индекс по (created_at, id): база читает его с конца и не сортирует всё;
- тест: запись с прошлой датой встаёт в конец, вторая страница продолжает с того же места, удалённый курсор не
  повторяет первую страницу.
