# Заголовок ответа — после всех чтений: иначе ошибка после него роняет процесс

Контекст: публичная ссылка без входа сначала отправляла заголовок 200, потом читала файл страницы; файла не было —
обработчик ошибок ответил 404 вторым заголовком, ERR_HTTP_HEADERS_SENT вылетел во внешнем обработчике и уронил
весь процесс сервера. Уронить его мог любой, у кого есть ссылка. Нашёл прогон API на стенде, не чтение кода.

Урок:
- Сначала прочитай и посчитай всё, что нужно для ответа (файл, данные), потом writeHead и end одним куском.
- После отправленного заголовка в обработчике ошибок — только end(), без нового статуса; проверяй res.headersSent.
- Регрессия — заглушкой ответа, которая считает вызовы writeHead: ровно один на запрос.
- Признак: writeHead стоит до readFileSync или await внутри try.
