# Дефолтные промты в БД: правка без архивной копии не доезжает до прода

Контекст: промты лежат в таблице и правятся из админки; в коде — словарь дефолтов, сидируемый при старте. Чтобы
не затирать ручные правки, сид обновляет строку только если её текущий текст совпадает с одной из ПРОШЛЫХ версий
дефолта. Меняешь дефолт, забываешь положить прежний текст в архив — прод молча остаётся на старом промте.
Симптом один: поведение ИИ на проде не меняется после деплоя, ошибок нет.

Урок:
- Изменение дефолтного промта — всегда пара правок: новый текст + прежний рендер того же слага в список архивных
  версий. Промт собирается из констант — архивная копия использует СТАРЫЕ константы (`_RULE_V1`).
- Регрессионный тест: текущий дефолт не лежит в архиве, последняя архивная версия не содержит маркера нового правила.
- После деплоя проверь в логе старта счётчик обновлённых промтов — единственное доказательство, что прод переехал.
