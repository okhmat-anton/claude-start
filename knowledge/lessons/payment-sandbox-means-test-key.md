# Плашка Sandbox / test mode на оплате — тестовый ключ шлюза в окружении сервера, не интерфейс

Контекст: владелец увидел плашку Sandbox на оплате; в коде кабинета слова «sandbox» нет. Платёжный шлюз выбирает режим
по ключу (тестовый ключ → тестовый Stripe), а на сервере с первого релиза остался тестовый ключ, хотя инструкция релиза
требовала живой. Поиск по интерфейсу ничего бы не дал.

Урок:
- Плашка тестового режима на оплате — это ключ в окружении сервера: сначала префикс ключа (`sk_test_` / `sk_live_`)
  в `.env` сервера, потом запрос к шлюзу его же ключом (`health`: режим и готовность), и только потом код.
- Секреты не печатать: префикс через `cut -c1-24`, ответы шлюза через маску длинных строк; перенос ключа между
  машинами — конвейером `grep | ssh 'sed -i'`, с резервной копией `.env` и только с разрешения владельца.
- После смены `.env` контейнер пересоздать (`docker compose up -d` показывает `Recreated`); перезапуск без
  пересоздания оставляет старое окружение.
- Признак: инструкция релиза говорит «живой ключ», а первый релиз делался тестовым — проверь, что его потом сменили.
