# Тест проверяет то, что приложение отдаёт, а не то, как оно устроено внутри

Контекст: смоук-тест «эндпоинт зарегистрирован» читал внутренний список маршрутов. На живом приложении все
маршруты работали, а тест упал: в свежей версии фреймворка подключённые роутеры хранятся вложенными объектами
с пустым путём, в запиненной — плоским списком.

Урок:
- Маршруты проверяй по схеме API (`openapi()`, `/openapi.json`) — списку путей, которые сервис объявляет
  клиенту; ответ — по статусу и телу; конфигурацию — по поведению кода, а не по внутреннему словарю настроек.
- Признак плохого теста: читает поле, не описанное в документации фреймворка как публичный интерфейс.
- Ради чего тест писался: роутер, выпавший из сборки, не синтаксическая ошибка и не падает до запроса клиента
  на проде. Тест на объявленные пути ловит это на месте.
