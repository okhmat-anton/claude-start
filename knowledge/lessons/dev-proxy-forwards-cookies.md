# Прокси разработки пропускает запрос и ответ целиком

Контекст: dev-сервер фронта проксировал `/api` к бэкенду своим обработчиком и отдавал только тело ответа:
вход на стенде отвечал 200, но `Set-Cookie` терялся, и текст ошибки бэкенда тоже. В проде `/api` шёл через
nginx мимо этого прокси, поэтому поломка жила только локально.

Тот же прокси второй раз: загрузка файла. Тело `multipart/form-data` читалось как текст (`readBody`), заголовок
`content-type` с границей частей не передавался — файл приходил на бэкенд битым, «загрузить фото» на стенде не работало.

Урок:
- Свой прокси API пробрасывает `set-cookie` (каждый) и тело ошибки бэкенда.
- `multipart` пересылается сырыми байтами (`readRawBody(event, false)`) вместе с исходным `content-type`.
- Проверяй по факту, через порт фронта, а не напрямую в бэкенд: вход — заголовком `Set-Cookie` и запросом
  «кто я», загрузку — настоящим файлом.
