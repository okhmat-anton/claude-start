# Меняешь правило поведения — найди все его старые формулировки, а ограничение в тексте сверь с источником

Контекст: длина кавера считалась «как у исходника» — так было написано в протоколе агента, в документации API и в
подсказках интерфейса на девяти языках. На деле это был наш хардкод: поставщик принимает любую длину. После смены
правила старая формулировка осталась в трёх местах и противоречила новой.

Урок:
- Прежде чем записать в протокол или документацию ограничение вида «X определяется Y», сверь его с параметрами
  поставщика или источника: возможно, это наш код, и ограничение снимается одной строкой.
- Сменил правило поведения — сделай grep ключевых слов старой формулировки по протоколам агента, документации
  API и словарям интерфейса всех языков. Не ищи только по имени поля.
- Признак: в тексте для людей стоит «как у», «берётся из», «всегда», «по умолчанию» рядом с тем, что ты меняешь.
- Цена: агент, читающий протокол, будет действовать по старому правилу и спорить с интерфейсом.
