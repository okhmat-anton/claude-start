# Пиксель + серверные события: Meta склеивает только пару «браузер → сервер»

Контекст: конверсию (заявку) сайт шлёт дважды — из браузера пикселем и с сервера, под одним номером события.
Попросили слать её ещё и на нажатие кнопки, а страница «спасибо» уже отправляла браузерную копию. Второй вызов
пикселя «в лоб» удвоил бы каждую заявку в отчётах.

Урок:
- По документации Meta два **браузерных** события с одинаковыми `event_id` и именем НЕ склеиваются; склеивается
  пара браузер + сервер, надёжно — когда браузерное пришло первым (окно 48 часов).
- Переносишь событие на действие в браузере — номер создаёт браузер и отправляет вместе с формой (скрытое поле),
  сервер проверяет формат (номер попадёт в `<script>` следующей страницы) и шлёт близнеца под тем же номером,
  а копию на странице после отправки глушит отметка «уже отправлено» в localStorage.
- Перед `form.submit()` — пауза ~0,4 с: без неё переход обрывает ещё не ушедший запрос пикселя.
- Проверка — настоящий браузер с заблокированным адресом отправки пикселя: в журнале сети видны порядок событий
  и их номера, наружу ничего не уходит. Номер пикселя в прогоне — выдуманный.
- Цена переноса на нажатие: нажатие, после которого заявка не сохранилась, тоже считается конверсией —
  это решение заказчика, назови его вслух.
