# Ревью кода и ревью глазами — параллельно: они ловят разное

Контекст: пока полчаса шёл последний круг ревью по кадрам, субагент упрощения читал дифф и его окружение. Он нашёл
три настоящих бага, которых на кадрах не было: склонение «1 поста» (на стенде английский), фильтр поиска с выражением
ORM вместо значения (кадр показывал поиск по имени) и кнопку «В друзья», которая не читала ответ сервера.

Урок:
- упрощение и улучшения по коду запускай одновременно с последним кругом ревью глазами, а не после: смотрят разное,
  время одно; правки клиента применяй после отчёта ревью, чтобы горячая перезагрузка не сбила ревьюера;
- в брифе упрощения — «каждое утверждение проверь по коду или прогоном»: баги приходят внутри «улучшений»;
- баг из отчёта упрощения — поломка задачи: чинить сразу, с регрессионным тестом.
