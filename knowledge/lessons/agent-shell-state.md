# Состояние шелла между Bash-вызовами агента не сохраняется

Контекст: агентный CLI-харнесс выполняет каждую команду отдельным вызовом. Симптомы: «command not found»
для curl/wc во втором вызове, хотя первый работал; скачанные или сгенерированные файлы лежат в корне
репозитория, а не в рабочей папке; ложный 401 из-за относительного пути к файлу с ключом.

Урок:
- Рабочую папку между вызовами харнесс то сбрасывает, то хранит (с осени 2026: `cd` в составной команде утаскивает
  следующие вызовы в чужую папку, и хуки считают её проектом) — в обоих случаях все пути абсолютные, переход — в той же команде.
- PATH бывает урезан: начинай команду с `export PATH=/usr/bin:/bin:/opt/homebrew/bin` либо зови бинари по абсолютному пути.
- Команда пишет файлы — сразу `ls` по абсолютному пути назначения. Тихое попадание файлов в корень ломает
  изоляцию клиентских папок, и замечается это после коммита.
- В zsh `path` — массив-двойник PATH, `status` — только для чтения: `for path in …` обнуляет поиск команд до конца
  той же команды (curl «not found» сразу после рабочего вызова). Переменные цикла — `p`, `route`, `item`.
- Строка в переменной zsh не делится на слова: `K="python3 tool.py"; $K lint` ищет команду с пробелом в имени.
  Сокращение — функция: `K() { python3 tool.py "$@"; }`.
- В zsh `?`, `*`, `[` в незакавыченном слове — шаблон файлов: адрес с `?key=` или маска без совпадений роняет
  команду «no matches found» до её запуска. Адреса и маски бери в кавычки.
