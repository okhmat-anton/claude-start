# Состояние шелла между Bash-вызовами агента не сохраняется

Контекст: агентный CLI-харнесс выполняет каждую команду отдельным вызовом. Симптомы: «command not found»
для curl/wc во втором вызове, хотя первый работал; скачанные или сгенерированные файлы лежат в корне
репозитория, а не в рабочей папке; ложный 401 из-за относительного пути к файлу с ключом.

Урок:
- `cd` прошлого вызова не действует: все пути — абсолютные; нужен переход — делай его в той же команде.
- PATH бывает урезан: начинай команду с `export PATH=/usr/bin:/bin:/opt/homebrew/bin` либо зови бинари по абсолютному пути.
- Команда пишет файлы — сразу `ls` по абсолютному пути назначения. Тихое попадание файлов в корень ломает
  изоляцию клиентских папок, и замечается это после коммита.
