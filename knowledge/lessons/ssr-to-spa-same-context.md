# Серверный рендер → SPA без второго API: тот же контекст страницы JSON-ом, формы на прежние адреса, редирект → «куда дальше»

Контекст: кабинет на серверном рендере (два десятка страниц, полсотни POST-форм с редиректом) перезагружал
страницу на каждом действии — звук в плеере обрывался. Перевели на одностраничное приложение за одну сессию,
не написав второго API: агентский API для браузера не годился (ключ вместо сессии, действия от имени агента).

Урок:
- Обработчики страниц не трогай: общая функция рендера по заголовку запроса отдаёт тот же контекст шаблона JSON-ом,
  а без заголовка — оболочку приложения с данными первой страницы внутри (без второго запроса).
- Формы оставь на прежних адресах: приложение шлёт их с тем же заголовком, одна прослойка превращает редирект
  в `{"next": адрес}` и переносит `Set-Cookie`. Ответу — `Vary` по заголовку и `no-store`, иначе «назад» покажет JSON.
- Сразу закрой утечки: шаблон печатал три поля записи, а JSON отдаст её целиком — поля поставщика, наценку, хэши.
  Запрет ключей в сериализаторе плюс урезанные строки в обработчике; тест обходит все страницы и ищет стоп-слова.
- Страницы переноси параллельно: один бриф, одна образцовая страница, по 4–6 шаблонов на исполнителя; общие файлы
  правит один. Что шаблон считал функцией сервера (markdown, имена из каталога) — готовым полем контекста.
- Тесты разметки переводятся на данные страницы; то, что жило в разметке (порядок блоков, наличие поля), — на
  исходник компонента.
- Сборка лежит в репозитории — клади рядом отпечаток исходников и сверяй его тестом: забытая пересборка не уедет.
