# Адреса в документах для агента — тест против роутера

Контекст: протоколы для внешнего агента (markdown с curl-примерами) переносились из прошлой версии API. В них
попадали старые пути и методы (PUT вместо PATCH, несуществующий `GET /project`); тесты кода такого не ловят,
а агент пойдёт по документу и получит 404/405 у пользователя.

Урок:
- Документ для агента с вызовами API проверяй тестом против роутера приложения: собери маршруты с методами,
  плейсхолдеры `<id>` и `{param}` сведи к сегменту, и каждый `BASE_URL/…` и строка «МЕТОД /путь» обязаны совпасть
  с живым маршрутом с этим методом.
- В том же тесте — шапка документа, язык, отсутствие имени поставщика; упоминание самой базы API разреши явно.
- Проверь, что страж ловит: скорми ему заведомо неверные путь, метод и адрес.
- Возможность, которой в API ещё нет, документ называет «ещё недоступно», а не описывает будущий адрес.
