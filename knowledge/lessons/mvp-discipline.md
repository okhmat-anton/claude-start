# MVP-дисциплина — ядро прежде обвязки

Контекст: post-mortem умершего прототипа — почти все ~50 коммитов ушли в обвязку (соцфункции, медиа, облачная
инфраструктура, админки), ядро ценности осталось на мок-данных, проект начали заново.

Урок:
- Ни строчки второстепенных подсистем, пока автор сам не пользуется ядром продукта в реальной жизни.
- Жёсткие этапы: следующий открывается, когда предыдущий работает в реальном использовании; список «чего
  сознательно НЕТ до этапа N» фиксируется письменно в DECISIONS.md — забор от расползания.
- Никакой тяжёлой инфраструктуры на ноль пользователей: SQLite + docker + файлы + дешёвый VPS; усложнять,
  когда реально упёрлись.
- Один критерий MVP: автор ежедневно пользуется продуктом. Агент сверяет с этим план каждой задачи.
