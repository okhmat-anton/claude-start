# Внедрение линтера в код, который никогда не проверяли

Контекст: проект с правилом «никаких пакетов» звучит как запрет на линтер; первый красный прогон на сотнях
замечаний объявляют шумом и выключают линтер навсегда. После настройки конфига осталась одна ошибка — и она
оказалась настоящим багом (имя функции на один символ отличается от объявленного).

Урок:
- «Ноль зависимостей» касается рантайма, а не машины разработчика: файл зависимостей содержит только раздел
  dev-инструментов; «не попадёт в образ» проверяй фактом — списком копируемых файлов. Запиши выбор в DECISIONS.md,
  иначе следующий снесёт линтер, сославшись на правило.
- Два уровня: быстрая проверка синтаксиса средствами языка (без пакетов, годится для хука после правки) и
  полный линтер на завершении задачи. Один тяжёлый прогон на всё начинают пропускать.
- Первый прогон: прогнать → отделить ложное (принятые идиомы, глобали из других файлов, неиспользуемая
  переменная ошибки) → починить конфиг под принятые приёмы → прогнать снова → только оставшееся читать как находки.
  Цель — список, в который поверят.
- Разделяй ошибки и предупреждения: хук после правки — в режиме «только ошибки», иначе на старом коде он заблокирует любую правку.
